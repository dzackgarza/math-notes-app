# Flutter owns the web interface

**Adopted: Flutter with Cupertino widgets for web and UIKit for iPad.** Flutter owns controls, navigation, focus, keyboard behavior, input dispatch, gestures, and scrolling. Its Cupertino controls and scroll behavior run on the web. The hosts share the existing C++ document engine and file format. Google Ink and Skia own ink and page rendering. ([Flutter Cupertino widgets](https://docs.flutter.dev/ui/widgets/cupertino), [Flutter web](https://docs.flutter.dev/platform-integration/web), [repository architecture](../ARCHITECTURE.md#component-ownership))

## Standard controls come with their interaction behavior

Flutter's Cupertino widgets provide the application shell and standard controls in one focus and input system. `CupertinoScrollBehavior` applies `BouncingScrollPhysics` to descendant `Scrollable` widgets. Its device setting can restrict scrolling to finger and trackpad input, while framework gesture recognizers can restrict the devices that start other interactions. `InteractiveViewer` supplies pan, pinch, scale bounds, and movement friction. **Its movement friction is distinct from the bounce supplied by a Cupertino scrollable**; selecting Flutter does not assert that a notebook surface gets every desired edge behavior from one widget. The framework provides these owners and the integration must show them working together on the target device. ([CupertinoScrollBehavior](https://api.flutter.dev/flutter/cupertino/CupertinoScrollBehavior-class.html), [ScrollBehavior.dragDevices](https://api.flutter.dev/flutter/widgets/ScrollBehavior/dragDevices.html), [GestureDetector.supportedDevices](https://api.flutter.dev/flutter/widgets/GestureDetector/supportedDevices.html), [InteractiveViewer](https://api.flutter.dev/flutter/widgets/InteractiveViewer-class.html))

Flutter web documents `HtmlElementView` for an HTML element inside its widget layout. The existing Skia canvas can be a passive rendering element with `pointer-events: none`; the Flutter surface then receives normal contact events. The selected HTML TikZ editor can remain an interactive iframe in another `HtmlElementView`, with its own internal input. Flutter also documents how to keep controls above an interactive HTML view responsive. These are standard browser integration points. ([HtmlElementView](https://api.flutter.dev/flutter/widgets/HtmlElementView-class.html), [Flutter HTML embedding](https://docs.flutter.dev/platform-integration/web/web-content-in-flutter), [TikZ integration](../ARCHITECTURE.md#integration-targets))

## The C++ core needs bounded host bridges

The web host calls the existing C++ WebAssembly engine and displays its Skia output. A browser pen adapter supplies **coalesced and predicted sample identity, pressure, and both tilt axes** for pen events accepted by the framework's notebook input target. Flutter retains hit testing, capture, cancellation, and focus, so a pen behind a dialog cannot start drawing. The app maps viewport coordinates and completed document commands to the engine. These operations connect the GUI to the document; they do not implement standard touch control. Flutter's web input adapter expands coalesced movements, but its public pointer event has one tilt value and no predicted-sample marker, so the ink record needs the raw browser fields. ([Dart JavaScript interop](https://dart.dev/interop/js-interop), [Flutter pointer binding](https://github.com/flutter/flutter/blob/main/engine/src/flutter/lib/web_ui/lib/src/engine/pointer_binding.dart), [Flutter PointerEvent](https://api.flutter.dev/flutter/gestures/PointerEvent-class.html), [Pointer Events](https://www.w3.org/TR/pointerevents3/))

## Qt remains the strongest alternative

Qt Quick with Qt Quick Controls also owns controls and input as one system. `Flickable` supplies velocity and rebound; `PinchHandler` supplies touch scaling; QML can call the C++ core directly. Qt's browser build supports Qt Quick Controls. ([Qt Quick Controls](https://doc.qt.io/qt-6/qtquickcontrols-index.html), [Flickable](https://doc.qt.io/qt-6/qml-qtquick-flickable.html), [PinchHandler](https://doc.qt.io/qt-6/qml-qtquick-pinchhandler.html), [Qt for WebAssembly](https://doc.qt.io/qt-6/wasm.html))

The relevant difference is what Math Notes would own on the **web**. Qt limits its iOS control style to macOS and iOS. Qt WebEngine is outside the WebAssembly module set, so the HTML TikZ editor would need an external browser overlay and focus bridge. Direct C++ calls do not supply these missing browser interface facilities. Flutter supplies a web Cupertino library and a documented HTML widget. Its standard Dart and JavaScript interop is an integration API, not a reason to prefer Qt by counting languages or dependencies. ([Qt iOS style](https://doc.qt.io/qt-6/qtquickcontrols-ios.html), [Qt for WebAssembly](https://doc.qt.io/qt-6/wasm.html), [Flutter HTML embedding](https://docs.flutter.dev/platform-integration/web/web-content-in-flutter))

The current Ionic, Framework7, and gesture packages split interface ownership. Editor SDKs such as tldraw and Nutrient own edits and undo in their shape or PDF models. Flutter owns the GUI while the C++ notebook remains authoritative. ([current web host](../ARCHITECTURE.md#current-web-host), [tldraw store](https://tldraw.dev/sdk-features/store), [Nutrient Web SDK](https://www.nutrient.io/api/web/index.html))

**Acceptance:** a Chrome pen and touch run must show full pen samples, finger pan and edge rebound, pinch, held page-end release, control and TikZ focus, and keyboard use. This tests the selected framework and its bounded bridges; it does not defer the framework choice.
