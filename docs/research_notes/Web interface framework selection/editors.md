# Browser editor SDK ownership

This note assesses complete document editor SDKs against the authoritative C++ engine. Its earlier DOM-host retention recommendation is superseded by the [full-framework assessment](../../reports/Web%20interface%20framework%20selection.md), which selects Flutter with Cupertino controls for the web interface.

## Which browser editor gives the most complete standard interface while the shared C++ engine remains authoritative?

### Takeaway

The surveyed complete editor SDKs store their own edited document state. Their normal ink tools, object editing, undo, and save behavior do not transfer directly to the authoritative C++ document without another model or substantial action translation. This finding supports selecting a complete GUI framework around the engine rather than adopting another document editor.

### Cited Findings

- Math Notes' engine owns discrete standalone SVG pages, Google Ink strokes, selection, erasure, and `DocumentHistory`; the web host supplies samples and renders the engine with Skia. The web and iPad interfaces are independent hosts. — [Architecture](../../ARCHITECTURE.md), [format](../../FORMAT.md)
- The requested viewport stacks fixed-size A4 pages with a narrow gap; pen draws, one finger pans, two fingers pinch, and a held bottom pull adds a page on release. — [Tablet interface](../../specs/tablet-ui.md)
- Framework7 9.1.2 documents bottom pull, threshold, pull progress, release, and completion callbacks. Its `page-content` uses browser scrolling. The web host already instantiates Framework7 pull on its editor scroll area and uses a pinch recognizer over that surface. — [Framework7 pull API](https://framework7.io/docs/pull-to-refresh.html), [Framework7 page CSS](https://github.com/framework7io/framework7/blob/v9.1.2/src/core/components/page/page.less), [current editor](https://github.com/dzackgarza/math-notes-app/blob/573e2e68fd22b3209978a97d513036ecf529058c/hosts/web/src/editor/Editor.tsx)
- The current web editor intercepts `touchmove` at the bottom edge and calls `preventDefault()` so Framework7 bottom pull starts. It also cancels the two-finger sequence for its pinch recognizer. The selected architecture is implemented in part, but this interception means native edge motion cannot be credited without device evidence. — [Current editor](https://github.com/dzackgarza/math-notes-app/blob/573e2e68fd22b3209978a97d513036ecf529058c/hosts/web/src/editor/Editor.tsx#L776-L800)
- Chromium's PDF viewer distinguishes pen drawing contact from touch scrolling by matching pointer and touch starts and cancelling only the drawing contact. Its tests exercise the pen/finger split. This is a reference for the narrow adapter between browser input and the existing engine. — [Chromium ink host](https://chromium.googlesource.com/chromium/src/+/be0366525a33fc4df00ab2b4164cb0f506dcc47b/chrome/browser/resources/pdf/elements/viewer-ink-host.ts), [Chromium gesture tests](https://chromium.googlesource.com/chromium/src/+/fcbdc2a473cb996c9e6b9382631ae8930924a22a/chrome/test/data/pdf/annotations_feature_enabled_test.ts)
- tldraw offers a substantially more complete canvas UI, including toolbar, menus, dialogs, actions, keyboard shortcuts, responsive behavior, pen detection, pinch state, camera momentum, and configurable camera bounds. Its own camera example includes A4 bounds. Infinite canvas branding is therefore not a reason to reject it. — [UI components](https://tldraw.dev/sdk-features/ui-components), [input handling](https://tldraw.dev/sdk-features/input-handling), [camera options](https://tldraw.dev/examples/camera-options), [editor options](https://tldraw.dev/sdk-features/options)
- tldraw's default editor operations act on its store of shapes, pages, bindings, and assets, and its undo manager records changes to that store. Custom shapes also require tldraw geometry, serialization, rendering, and store schema. Its custom renderer example hides its normal shape layer with CSS and says consumers may set the Canvas component to `null` to render everything themselves. — [Store](https://tldraw.dev/sdk-features/store), [history](https://tldraw.dev/sdk-features/history), [custom shape](https://tldraw.dev/examples/custom-shape), [custom renderer](https://tldraw.dev/examples/custom-renderer)
- Nutrient Web SDK supplies a complete PDF viewer/editor UI, page rendering, annotations, customization slots, and client-side execution. Its default ink toolbar creates Nutrient ink annotations on a PDF document. — [Web SDK](https://www.nutrient.io/api/web/index.html), [annotation presets](https://www.nutrient.io/guides/web/customizing-the-interface/using-annotation-presets), [SDK samples](https://www.nutrient.io/guides/web/samples/)
- Wacom Digital Ink Web can route pen-only input and retain sensor samples, including coalesced and predicted points. This is an ink input/processing SDK, not a full notebook viewport and interface owner. — [InputListener](https://developer-docs.wacom.com/docs/sdk-for-ink/api/digital-ink-web/InputListener/), [sensor points](https://developer-docs.wacom.com/docs/sdk-for-ink/api/digital-ink-web/InkInput/)
- Xournal++ describes its former Flutter web/mobile application as stalled and no longer available. Its maintained primary app targets GTK desktop systems. — [Xournal++ repository](https://github.com/xournalpp/xournalpp)

### Inferences

- Using tldraw as a shell over an independent Skia page canvas would inherit its camera and chrome. Its default editing actions would then target tldraw records, while the actual objects and history would remain in C++. Making those actions meaningful requires mirrored shape state, transaction translation, or replacements for much of the default UI. A page-proxy shape per SVG page makes the data mirror smaller but does not make tldraw's element selection, eraser, or undo act on the SVG contents. Its custom renderer is a viable integration seam, not proof of full editor ownership.
- Nutrient has the closer fixed-page visual model. Feeding it generated PDF backgrounds and mapping its annotations back to editable SVG/Google Ink would nevertheless produce two competing ink and history models. A read-only Nutrient viewer with a C++ ink overlay similarly discards the SDK's default annotation workflow. Neither route minimizes novel maintained behavior under the current authoritative core.
- Framework7 plus Ionic is the narrowest migration from the current DOM host: browser scrolling supplies fling and edge behavior; Framework7 supplies bottom pull; Ionic supplies controls; Math Notes owns page placement, pen sample routing, scale/coordinate mapping, and the add-page command. It avoids duplicating document transactions but keeps several interaction owners on one touch surface.

### Gaps

- The combined pen, one-finger fling and bounce, pinch, and bottom-pull behavior has not been proven on the supported pen/touch device. Framework7's pull source tracks one touch identifier and documents no pinch-arbitration contract; the app must demonstrate simultaneous integration rather than treat separate API coverage as proof. — [Framework7 pull source](https://github.com/framework7io/framework7/blob/v9.1.2/src/core/components/pull-to-refresh/pull-to-refresh-class.js), [current UI decision](../Component%20ownership%20decisions/ui.md)
- No tldraw documentation inspected establishes a bottom-edge held pull-to-add action or iOS-style elastic edge behavior. Its camera documentation establishes bounded movement, momentum friction, and zoom; a working device demonstration would be needed to credit those additional behaviors. — [Camera system](https://tldraw.dev/sdk-features/camera), [editor options](https://tldraw.dev/sdk-features/options)

## What is the exact integration boundary and why are other complete SDKs not selected?

### Takeaway

The web editor keeps a single authoritative document and history in C++. A complete GUI framework can own input dispatch, viewport position, zoom, and generic controls around that core. A third-party document editor would also need its normal tools and undo to operate on the C++ document without parallel authoritative state.

### Cited Findings

- tldraw allows a bounded camera with independent horizontal and vertical constraint behavior, `fit-x` initial zoom, and controlled wheel behavior. Its UI slots and actions can be overridden. — [Camera system](https://tldraw.dev/sdk-features/camera), [UI components](https://tldraw.dev/sdk-features/ui-components), [actions](https://tldraw.dev/sdk-features/actions)
- tldraw's production use requires an active license key (trial, commercial, or discretionary hobby); its default license permits development use only. The license allows modification and bundling, so a licensed fork is possible. Offline key enforcement and data collection terms require a concrete agreement before an offline product could adopt it. — [tldraw license](https://github.com/tldraw/tldraw/blob/main/LICENSE.md), [license guide](https://tldraw.dev/community/license)
- Nutrient Web SDK is available as a client-side JavaScript/WASM product with a production license; its documented input files include PDF, office documents, images, text, XFDF, and Instant JSON. Its built-in page and annotation UI can be customized. — [Nutrient API overview](https://www.nutrient.io/api/web/index.html), [SDK samples](https://www.nutrient.io/guides/web/samples/)
- MyScript iink JIIX can export stroke and recognition information, so it should not be rejected as incapable of exporting ink. Its documented exchange format is JIIX, whereas Math Notes' document contract is independent page SVG and authored figure source. — [JIIX reference](https://developer.myscript.com/doc/interactive-ink/4.1/reference/jiix/), [Math Notes format](../../FORMAT.md)
- Excalidraw exposes a complete embeddable editor component, but its documented API takes Excalidraw elements and app state as the editing model. — [Excalidraw component props](https://github.com/excalidraw/excalidraw/blob/master/dev-docs/docs/%40excalidraw/excalidraw/api/props/props.mdx)

### Inferences

- The current DOM adapter renders each engine page in Framework7 scroll content, translates pen samples and scroll/zoom coordinates into `ink_input`, and calls the add-page command after Framework7 reports a held bottom release. Each step maps a host event or representation. This path remains evidence for the alternative, not the selected web framework.
- A tldraw pilot would need a custom Skia Canvas component synchronized to its camera, locked page proxies or no tldraw shapes, input routing from its events to `ink_input`, custom tool actions for core commands, and a decision on whose selection and undo UI is authoritative. Those are feasible bridges, but their scope removes much of the inherited UI behavior being sought. This is the precise integration cost; framework size and its infinite canvas marketing are not decisive objections.
- A Nutrient pilot would need to decide whether PDF annotations become the editor of record or are continuously translated to the engine's SVG objects and original pen samples. The latter translation is a second editor integration, not a representation-only adapter. Its PDF and annotation strengths are valuable for imported PDF viewing but do not warrant replacing the notebook editor while C++ owns native SVG edits.

### Gaps

- A direct prototype could falsify this selection if tldraw's normal selection, erasure, history, and bottom interaction can be mapped onto the existing C++ model with a small stable adapter. Its documented APIs do not establish that. — [Store](https://tldraw.dev/sdk-features/store), [custom renderer](https://tldraw.dev/examples/custom-renderer)
- Commercial Nutrient pricing and tldraw production/offline license terms depend on a vendor offer. No price estimate is used as a selection reason. — [Nutrient licensing entry](https://www.nutrient.io/api/web/index.html), [tldraw license](https://tldraw.dev/community/license)
